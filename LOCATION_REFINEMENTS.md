# JOIN location, creation, map and Profile refinements

No deployment, commit, push, dependency upgrades, payment flow or Passport implementation is included.

## Failure investigation and evidence limits

**Website location:** obtaining coordinates and obtaining a place label were conflated. The installed Expo 48 location implementation routes `reverseGeocodeAsync` on web through Google geocoding, which requires `setGoogleApiKey`. JOIN does not configure that service. The fallback used a browser MapTiler key; a missing key, failed request or empty result still produced “Current location unavailable” even after successful browser positioning. The old request also demanded high accuracy with no cached fix, and cached permission denial for the session. Those paths could prevent subsequent acquisition or recovery. There is no need to add a Google provider.

The updated flow calls `navigator.geolocation.getCurrentPosition` on web, checks secure context, uses a balanced browser fix with a 15-second timeout and at most 60-second age, distinguishes permission denial/unavailable/timeout/unsupported/HTTPS errors, and permits recovery after permission changes. A failure clears the in-memory fix. Profile uses only the device-derived result, offers Retry, and distinguishes a successful position with unavailable place labels. Native retains OS reverse geocoding. Neither flow substitutes a city.

**Publish:** the previous Review handler always called a separate, global, browser-side `geocodeActivityLocation` before making the creation API request. Missing MapTiler configuration, provider errors or no matching feature threw a plain Error. The catch displayed only `error.response.data.message`, discarding plain geocoding errors and backend `{errors: [...]}` validation responses. A valid draft with its default category cover therefore could show the generic failure without ever reaching the backend. A title of one or two characters also passed the old client check but failed backend validation with the same generic message.

The wizard now requires an actual selected coordinate in its location step and publishes it without a second geocode. Title minimum validation matches the server. API field errors are displayed without echoing input values. ISO conversion, privacy flags, idempotency keys, image validation/upload claims, R2 storage and activity persistence remain in their existing paths. Default covers remain a client category image; they do not require R2 or an enabled image-upload switch. There are no new notification side effects on creation.

These are source-confirmed, reproducible failure paths, covered by tests. Production request logs, the failing request ID, live environment values and an authenticated production browser session were not available. Consequently the exact provider/environment failure for the reported production incident is **not independently confirmed**. No production activity was created as part of this work.

## Current-region contract and privacy

- Authenticated `POST /api/locations/current` accepts a numeric device latitude/longitude. Radius, expiry and label are determined by the server; client-supplied radius/label fields are ignored.
- A region is a **50 km great-circle radius** around the recent device fix, valid for **30 minutes**, with no city-name matching. This intentionally approximates a surrounding local area rather than exact municipal boundaries. The radius is the same for all locations; Perth/Phuket are not special-cased. Changing this product boundary requires changing `REGION_RADIUS_KM` and reviewing tests.
- The client receives the server's radius/expiry and checks it before place or map selection. The server independently checks activity creation and coordinate edits. Missing/expired regions fail closed. Out-of-region points return exactly: `Passport Mode is required to host activities in another location.`
- Discovery requires authentication and a current region. MongoDB spherical filtering happens **before pagination**, including at the antimeridian. Existing direct activity links and membership/history access retain their privacy/access logic; a current region is not required merely to view a joined activity.
- The feed registers a fresh/cached device fix before discovery. The location picker explicitly refreshes it. Revisiting/retrying the location step refreshes a region that expires during a long draft.
- Private coordinates are held in a separate `DeviceRegion` collection keyed to the authenticated user, never in a public user or activity response. MongoDB TTL removes expired records asynchronously; reads enforce expiry immediately. The owner-only response uses `Cache-Control: no-store`. Ordinary location diagnostics do not log coordinates or provider URLs.
- Only a friendly municipality/region/country provider label is written to Profile. Old manually stored labels do not determine the region. A failed label lookup after movement clears a previously stored label instead of reusing it. The general profile edit endpoint rejects manual location overrides. Public display still obeys `locationPublic`.
- Browser/native coordinates are client-reported. A modified client can spoof device positioning itself; browser APIs provide no cryptographic proof of physical presence. The server prevents substituting an arbitrary activity point outside the registered region, but this is not location attestation or anti-GPS-spoofing.

## Autocomplete, maps and request costs

The existing MapTiler provider is reused through an authenticated backend proxy, with the private server key kept out of the web bundle. Search uses MapTiler proximity and bounding-box parameters, returns at most six suggestions with name/context, then independently applies the circular radius filter. Queries need 3–120 characters. See [MapTiler geocoding API](https://docs.maptiler.com/cloud/api/geocoding/) for the provider's proximity, bounding-box and type semantics.

Client safeguards: **450 ms trailing debounce**, cancellation of pending timers, generation checks that ignore stale responses, two-minute cache bounded to 50 entries, and a rolling maximum of **12 uncached search requests/minute per app session**. Selected places do not trigger another search; selecting or publishing does not generate a second place lookup. Coordinate edits use the same bounded search proxy.

Server safeguards, installed before the provider is callable:

- Authentication on both location endpoints.
- **40 requests/IP/minute** and **20 requests/user/minute** across those endpoints, plus the application's existing global limiter. Minute limiters use process memory; each replica has its own minute window.
- Persistent atomic MongoDB budgets across **all replicas**: **200 provider requests/user/UTC day** and **1,000 provider requests total/UTC day**. Both forward and reverse geocoding consume these budgets. Concurrent attempts cannot exceed the shared cap. Budgets fail closed if their store is unavailable. Failed provider attempts still consume budget; there are no automatic provider retries.
- Eight-second provider timeout and maximum six results/request. A recent device-derived label can be reused within approximately 1 km for the region lifetime. Provider outages and exhausted budgets produce a safe unavailable state.

**MapTiler geocoding and existing MapTiler map sessions/tiles can incur usage-based charges.** No provider requests were billed during automated tests; provider responses were mocked. New geocoding is OFF by default. To enable later, explicitly supply `MAPTILER_SERVER_API_KEY` and `LOCATION_GEOCODING_ENABLED=true` on the backend after confirming these caps fit the account plan. This task does not change live settings. At full use, the new proxy permits at most 1,000 upstream attempts/day per shared database, approximately 30,000–31,000/month; this is a request ceiling, not a price quote. Existing maintenance/backfill scripts are separate operator-invoked jobs and are not covered by the interactive proxy budget.

The existing public map key remains separate (`EXPO_PUBLIC_MAPTILER_API_KEY`). Browser SDK map traffic goes directly to the provider and is **not capped by the server geocoding budget**. Retain provider origin restrictions, account quotas and billing alerts for that key. The create-location map reuses the existing Leaflet/OpenStreetMap preview; it adds no new paid provider. OpenStreetMap tiles and Leaflet CDN are external network requests and retain attribution. Native preview uses the existing native map provider. Device/map areas are necessarily disclosed to the map/geocoding provider used, but not to other JOIN users.

The location-step map starts around the device region, supports pan/zoom, recenters when a suggestion is selected, and shows a pin for the selected activity point. Tapping either web or native maps selects an in-region meeting point; outside clicks are rejected without moving the selection. It does not publish a user's device coordinates as an activity point automatically. Map-selected labels remain editable meeting-point text; map clicks do not cause unbounded reverse geocoding.

The main Map mounts independently of feed loading/failure/emptiness. Zero activities means an empty marker array and a subtle message over the interactive map. Denial uses the last valid local viewport without a live user dot; no available viewport means a location-unavailable state with Retry/recenter. Precise activity visibility continues through the existing activity privacy sanitizer.

## Profile

Identity includes photo, name, friendly device location, retry, Passport explanation, a single about line and Edit profile. Hosted/Joined are the only core stats. Latest Moment has a compact optional layout; history and all moment interactions remain available. Languages, age range, optional Instagram, interests and saved-activity information share the details surface. Location/about are not repeated there. Redundant Verification badges and the separate photo explanation card were removed; the photo requirement remains visible. Own and public Profile have no rating/reviews presentation; legacy fields and ratings on unrelated activity screens remain compatible.
